## 1. 提交前自动校验（6 项）

`commit.sh` 会在 `git commit` **之前**跑完这 6 项，任一失败即中止：

| # | 校验 | 期望 | 失败含义 |
|---|---|---|---|
| 1 | bib 三处条目数一致 | `204/204/204` | 某处漏拷 |
| 2 | `sections/` 根目录 == `main_clean`（除 `11_conclusion`） | 完全一致 | 两树不同步 |
| 3 | 根目录仍保留 `11_conclusion.tex` | 存在 | 被误删 |
| 4 | 无冲突标记 `<<<<<<<` / `>>>>>>>` | 0 | 有未解决冲突 |
| 5 | bib 花括号平衡 | depth = 0 | bib 损坏 |
| 6 | 无残留 `\revadd`/`\revdel` 标记宏 | 0 | 干净树里混进了标记稿 |

```bash
./commit.sh --check-only      # 只做校验不提交
```

### 期望输出

```

  ✓ 在 git 仓库内    /…/SurveyOfFTSG

══ 2 · sections 两树同步 ══
```

## 5 · 推送

```bash
cd "$REPO"
git push origin main
```

> ⚠️ 若远端在你侦察后**又**有新提交，push 会被拒（non-fast-forward）：
> ```
> ! [rejected]  main -> main (fetch first)
> ```
> 处置：
> ```bash
> git fetch origin
> git --no-pager log --oneline HEAD..origin/main    # 看远端多了什么
> git rebase origin/main                            # 或 git merge origin/main
> ./verify.sh                                       # 重新校验
> git push origin main
> ```

### 推送后

```bash
git --no-pager log --oneline -3
git status -sb
```

## 6 · ⚠️ 推送前必须处理：回信数字不一致

**这是一个已知的、不该静默合并出去的问题。**

### 现状

| 位置 | 写的是 | 与稿件实际 |
|---|---:|---|
| `d90bd4d` 提交的回信 | **222** 条参考文献 | ❌ 稿件是 **199** |
| `response_to_reviewers_final.md` | 4 处 `131`、2 处 `222` | `131` ✅ / `222` ❌ |
| `response_to_technical_check_final.md` | 1 处 `222` | ❌ |
| `修改内容清单_20260913.md` | 12×`131` 9×`222` 6×`130` 2×`303` 2×`129` 1×`228` 1×`207` 1×`199` | 混杂 |

### 为什么出现

`d90bd4d` 当时的 `.bbl` 确实是 **222** 条 bibitem（当时 `ultimate_complete.bib` 有 303 条，
正文引用 222 条）。本轮去重后正文引用降到 **199**，回信**没有跟着更新**。

### 处置

```bash
cd "$REPO"
grep -rn '222' --include="*.md" . | head -20
```

**不要**机械全局替换 —— `222` 可能出现在日期、页码、其他数字语境中。
逐处确认后改为 `199`。

> 建议在推送**同一个提交或紧随其后的提交**里修好，
> 否则审稿人会发现回信与稿件对不上。

## 7 · 追踪的编译产物怎么处理

> **✅ 本节已完成（2026-09-13）**：本轮新增的 11 个中间产物已 `git rm --cached`
> 移出版本库，并写入 `.gitignore` 防复发。
> **已跟踪**的关键产物（`is26.pdf` / `is26.bbl` / `is26_redline.pdf` /
> `is26_redline.bbl` / `Figure*.pdf`）**有意保留** —— 它们不受 `.gitignore`
> 影响，仍正常提交。以下是当时记录的决策依据。

⚠️ 仓库当前**把 LaTeX 中间产物也纳入了版本控制**：
```
is26.aux  is26.bbl  is26.blg  is26.fdb_latexmk  is26.fls
is26.log  is26.out
is26_marked.aux  is26_marked.bbl  is26_marked.blg  is26_marked.log  is26_marked.out
```
（以及 `SurveyOfFTSG-main_clean/` 下同名的一批）

### 为什么本轮**不要**顺手清理

- 本轮目标是**最小化可解释的改动面**。顺手加 `.gitignore` 会让 diff 膨胀、
  也让审稿留痕变得混乱。
- `.bbl` 其实**有理由**提交（有些投稿系统只收 `.bbl`，不跑 `bibtex`）。

### 建议的后续动作（本轮之后单独一个提交）

```bash
cat >> .gitignore <<'EOF'

# LaTeX build artifacts
*.aux
*.blg
*.fls
*.fdb_latexmk
*.log
*.out
*.synctex.gz
EOF
# 注意：*.bbl 不加 —— .bbl 有意保留
git rm --cached is26.aux is26.blg is26.log is26.out
git rm --cached SurveyOfFTSG-main_clean/is26.aux SurveyOfFTSG-main_clean/is26.blg \
                SurveyOfFTSG-main_clean/is26.log SurveyOfFTSG-main_clean/is26.out
git commit -m "chore(gitignore): 不再跟踪 LaTeX 中间产物（保留 .bbl）"
```
