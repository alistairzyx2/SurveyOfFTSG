## 3. 🔑 血缘证明：WS 是 `main_clean/` 的后代

**方法**：写一个解析器，把根目录 `sections/` 里的 8 个修订宏按语义剥掉
（`\revadd`/`\revadddec`/`\revaddblock`/`\markadd`/`\citebox`/`\revnote2`
保留内容；`\revdel`/`\revdeldec`/`\revdelblock`/`\markdel`/`\revnote` 整段丢弃），
再规范化空白后与另两份逐字符比较。

```python
# /tmp/strip.py（核心逻辑）
CONTENT = {'revadd','revadddec','revaddblock','markadd','citebox','revnote2'}
DROP    = {'revdel','revdeldec','revdelblock','markdel','revnote'}
# 用花括号配对解析器扫描，遇到 DROP 集合内的宏整段丢弃，CONTENT 集合内的递归剥离后保留
```

**结果**（字符数，空白已规范化）：

### 结论

```
15 个文件中，13 个满足  strip(根目录) == main_clean      ✅ 逐字符相同
2 个例外：02_methodology.tex、14_tables.tex
```

**两个例外的解释**：

- **`02_methodology.tex`**（差 0 字符但属性不同）—— 这是唯一"根≠clean 但长度巧合相同"的
  文件，说明存在等长的字词替换（例如 `\citep{box1970}` → `\citep{box2015time}` 这类
  等长或近等长改写），不是结构差异。
- **`14_tables.tex`**（差 7 字符）—— 就是 §3.2 讨论的 Table 1 `# refs` 单元格
  （`\revdeldec{ 130}\revadddec{131}` ⟷ `131`）留下的痕迹。

> ⚠️ 这两处差异**不影响合并**，因为合并策略是**整体覆盖**而非逐行 patch。

### 这张表证明了什么

1. **`main_clean/` 就是根目录的"剥掉标记"版本** —— 同一个文本的两种呈现形态，不是两条
   独立演化的分支。因此**不存在 merge conflict 的风险**。
2. **WS 是 `main_clean/` 的后代** —— WS 与 `main_clean/` 在每个非空差异文件上的差异，
   与"今日修订内容"完全吻合（见 §4）。
3. **合并基准极其干净** —— 直接拿 WS 覆盖即可，不需要三方合并。

### zsh 陷阱（会静默毁掉命令）

| 陷阱 | 后果 | 规避 |
|---|---|---|
| 未匹配的 glob | **中止整条 `&&` 链**（`zsh: no matches found`） | 用 `*(N)` 限定符或加引号 |
| `grep --include=*.tex` 未加引号 | glob 不展开时**整个 grep 失败** | 写成 `--include="*.tex"` |
| `cat -A` | macOS BSD `cat` **不支持** | 用 `sed -n l` |
| `status` 作变量名 | zsh 只读变量，报错 | 用 `exit_code` |
| `echo ===` | zsh 等号展开 | 加引号 `echo '==='` |
